# Recipes: common changes, step by step

Each recipe lists every file to touch. After any change, run the backend tests and the e2e smoke test (see [development.md](development.md)). If the change is visible to users, update `README.md` (the project page).

## Add a Python function the page can call

1. Write it in `backend/cerebro_q/api.py`:
   - it returns `_json({...})`;
   - its inputs are plain values or one JSON string;
   - heavy imports go inside the function.
2. Expose it to the local harness:
   - add its name to `FUNCIONES` in `tools/dev_server.py`;
   - add `export const nombre = fn("nombre");` to `tools/qollab_shim/puente_api.js`.
3. Add a wrapper to `py` in `frontend/js/python.js`. If it is slow (seconds or more), add its name to `LENTAS` and let callers pass `{ vigente }`.
4. Add a test in `tests/backend/test_cerebro_q.py` and a row to the API table in [backend.md](backend.md).

## Add an achievement

1. Add an entry to `LOGROS` in `frontend/js/juego.js`: `clave: { t: "Title", d: "One line saying what happened physically." }`.
2. Trigger it with `this._logro("clave")` inside `Juego.paso(r, ctx)` (per measured step) or `Juego.conducta(ev)` (per behaviour). Use only fields already in the step result ([backend.md](backend.md)); never invent a score.
3. The banner, chime and screen-reader announcement happen automatically (`mostrarLogro` in `main.js`).

## Add or change a neuron behaviour

1. Edit the table in `frontend/js/conducta.js`. Each entry needs:
   - `patron`, a regex on the neuron name;
   - `clase` and `texto`;
   - `programa`, an existing motion program;
   - `empuje`, the forward/backward drive;
   - `ref`, the literature.
2. A new motion program needs a `case` in `WormScene.actuar` (`frontend/js/escena.js`). If it bends the body, add its **curvature** term to the `kappa(s)` function in `_writeMotion` (plus an eased value in `MOTION_REPOSO` / `MOTION_TAU`). The shader and `deform()` read the same curvature table, so nothing else changes. Add it to `ACERCAR` in `main.js` if the camera should fly in.
3. Optionally add a sound cue in `Sonido.conducta` and an achievement.
4. Update the table and caveats in [behaviour.md](behaviour.md). Add the neuron and its expected `programa` to `ESPERADO` in `tests/e2e/smoke_test.py`, which checks a sample of neurons against the table.

## Add a HUD control or setting

1. Add markup in `frontend/index.html`: inside `#hud-deck` for the main controls, or inside `#lab` for the settings menu. Use `.lbl`, `.field-head` and a `?` help button (`data-help="key"`) if the term needs explaining.
2. Add the help text to `HELP` in `main.js`, and wire the control in `bindUI()`. For a slider, also set `aria-valuetext`.
3. If it changes the physics, read it in `physics()` / `previewParams()` and call `prefetchPreview()` on `change`.
4. Add the id to the DOM contract table in [frontend.md](frontend.md). Check it on a phone (≤ 980 px, `(pointer: coarse)`).

## Change a colour or the type

- **Colours are tokens** in `:root` of `frontend/main.css`. Keep the meaning:
  - `--q` cyan: quantum, superposition, theory;
  - `--spike` orange: measured, spike, laser;
  - `--warn` yellow: hardware;
  - `--bio` teal: behaviour.

  Check contrast (≥ 4.5:1 against `--void`) and note it in the comment.
- **The same colours are repeated outside the stylesheet**, so update them there too:
  - `SERIES_COLORS` in `frontend/js/graficos.js`;
  - hex colours in `frontend/js/escena.js` (rings, halos, laser, flash, trail, colormap `STOPS`).

  `main.js` reads `--spike` from CSS.
- **Fonts:** run `python tools/embed_fonts.py` (needs `pip install fonttools brotli`). Never edit the `FONTS:BEGIN/END` block by hand.

## Change the 3D body

The whole model is generated by `tools/blender/modelo_gusano.py` (Blender, headless). Change the script, rerun it (command in [3d-model.md](3d-model.md)), check its preview renders and the "somas inside" count it prints, then run `python tools/optimize_glb.py`. Organs are recognised by object name (`ORGANOS` in `escena.js`) and get their look from `MATERIAL_ORGANO`; a new organ needs an entry in both. Keep the file well under 2 MB (it is about 600 KB; it travels as base64 through Pyodide).

## Change the cascade physics or its numbers

- Window, circuit, post-selection: `backend/cerebro_q/cascada.py` (see [cascade.md](cascade.md)).
- Any number quoted on the card or in the docs must come from `tools/zeno_analysis.py` or a test. Re-run them, and update `TestZeno`, the card's τ table and [cascade.md](cascade.md) together.

## Publish to Qollab

Run `python tools/build_qollab.py`, then upload the contents of `dist/qollab/` keeping its folders. `README.md` is the project page. The details are in [development.md](development.md). Never copy files back from Qollab into the repo.
